## Architecture

The designated `/checkout/` route hosts exactly one native Woo Checkout Block. Its existing static ancestor becomes the fixed modal shell; no React input, payment control, cart or checkout lifecycle is remounted. Close/backdrop/Escape returns to the accepted storefront with the native session intact. Only its menu scroll position is retained in a one-use sessionStorage UI key; no cart/customer/order state is duplicated. The immutable source is `5e7836e22110ec076603bb1fa2b12f8bb90ee756:index.html`.

The shell restores 1040px width, 24px total viewport clearance, 92vh maximum height, 22px padding, 28px desktop radius and the exact shadow/backdrop. Source composition switches to one column at 1050px, and the bottom-aligned mobile panel/25px top corners at 700px. This supersedes the V2 701px two-column adaptation. Native action presentation is measured into the summary lane without moving its React-owned node or changing submission.

## Native fields and email

Customer fields: required Имя, Телефон, Адрес; optional Населённый пункт, Подъезд, Домофон, Этаж, Квартира / офис, and the ordinary native optional customer note. Existing explicit required privacy consent and native legal/terms remain. Surname, company/address2, country/state/postcode, contact/email/guest text are not customer-facing. Native country context is RU. Pickup is exactly `Симферополь, Кечкеметская улица, 1`; COD remains native.

Official Woo 11.1.2 source was downloaded from `https://downloads.wordpress.org/plugin/woocommerce.11.1.2.zip` into the ignored QA runtime. `BillingAddressSchema::get_properties()` requires email and `OrderController::validate_email()` rejects an empty/invalid email independent of locale. Country locale alone cannot remove that requirement.

Compatibility uses a per-native-session HMAC identity at the reserved non-deliverable `checkout.rollsbar.invalid` domain. It is explicitly internal compatibility data, never a customer contact. Server customer initialization, pre-dispatch native REST payload preparation and the public Woo cart-store actions preserve country/email during initialization. Native `defaultFields.hidden` removes the email control while keeping the required contact block lifecycle; CSS suppresses only its now-empty step presentation. Checkout registration is disabled and guest `create_account` is false. `pre_wp_mail` blocks messages addressed to the internal identity before mail transport. Native admin Reply-To headers pointing to it are removed, and operator email bodies mark email as not provided; operator delivery is preserved. No alternative order endpoint, schema bypass or account is introduced.

Field visibility/requiredness uses RU locale and the native fields registry before core registration. Woo 11.1.2 deliberately keeps country visible in locale because it is the locale lookup key. Country therefore remains a valid required native RU control, omitted only from customer-facing presentation; its value is submitted normally. Email is independently absent through native field configuration and has a seeded compatible value. The supported locale mechanism is documented at [Woo field removal](https://developer.woocommerce.com/docs/block-development/extensible-blocks/cart-and-checkout-blocks/removing-checkout-fields/). Public registry configuration is pinned and tested against 11.1.2. No Woo update is included.
